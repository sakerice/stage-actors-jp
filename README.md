# 日本の商業舞台俳優 評価ランキング

商業舞台（ミュージカル / ストレートプレイ / 2.5次元 / 宝塚OG / 歌舞伎）を主戦場とする俳優 60 人を、
Web 上に公開されている情報だけから機械的に評価して並べた 1 ページの静的サイト。

**Wikipedia / Wikidata は使っていない。** 以前の版はページを開くたびに Wikidata を叩いていたが、
現在は下記のソースを収集スクリプトで巡回し、結果を `data/ranking.json` に固めて配信している。

## 評価軸

| 軸 | 重み | 取得元 |
|---|---|---|
| X フォロワー数 | 22% | あちこちデータ（人物ページ）／取れない人は公開プロフィールの手入力スナップショット |
| Instagram フォロワー数 | 18% | 同上 |
| X 投稿頻度 | 10% | **自動取得不可**。`data/roster.json` の `xPostFrequency` に手入力した場合のみ使う |
| ニュースに取り上げられた度合い | 28% | ステージナタリー。直近12ヶ月の記事数と、その記事の注目度の合成 |
| 直近の活動量 | 22% | ステージナタリー。直近90日の記事数・最新記事の新しさ・掲載中の出演公演数の合成 |

芸歴（デビュー年からの年数）と年齢は**スコアに入れない**。表では参考値として出すだけ。

### 欠測の扱い

フォロワー数が無いときは 3 状態に分ける。ここを雑にすると順位が事実と食い違う。

| 状態 | 表示 | スコア |
|---|---|---|
| 数値が取れた | 数値 | 正規化して算入 |
| 本人名義のアカウントが無いと確認済み（`roster.json` の `noAccount`） | アカウントなし | **0 点として算入** |
| アカウントは見つかったが数値が無い | 未計測 | 下位 25% 相当の代替値を当てる |
| アカウントの有無自体が未確認 | 未確認 | 同上 |

「未確認」を 0 点にすると、SNS をやっていない人と、調べきれていない人が同じ扱いになってしまう。
確認が取れたものだけ `noAccount` に書くこと。

欠測軸を**外して重みを他へ按分すると「測れない人ほど有利」という逆転が起きる**
（SNS を測れない人が報道量だけで上位に来てしまう）。そのため、一部の人だけ欠測している軸は
外さず、実測できた人の下位 25 パーセンタイル相当を代替値として当てている
（`scripts/score.mjs` の `UNMEASURED_PERCENTILE`）。

例外は**全員分の数値が無い軸**で、これは全員同条件なので軸ごと落として重みを按分する。
現状は X 投稿頻度がこれにあたり、ページ上でも「現在は不使用」と表示される。
各行には実測できた軸の数（`4/4 軸実測` など）を出している。

フォロワー数は対数をとったうえで、**下限を 1,000 人に固定して**正規化している
（最小値を基準にすると、アカウントを持たない人を同じ物差しに乗せられないため）。

## 構成

```
index.html                 表示のみ。数値は持たず data/ranking.json を読む
data/roster.json           手で管理する名簿（ジャンル・事務所・各ソースの ID・手入力の補完値）
data/ranking.json          収集スクリプトが生成する成果物。直接編集しない
scripts/sources.mjs        各ソースの取得・パース
scripts/score.mjs          スコア計算（重み・正規化・欠測の扱い）
scripts/update-ranking.mjs 収集してスコアを計算し data/ranking.json を書き出す
scripts/rescore.mjs        収集済みデータからスコアだけ再計算（重み調整用・再収集不要）
scripts/verify-ranking.mjs 生成物の健全性チェック（HTML 構造が変わって全欠測になるのを防ぐ）
scripts/should-run.mjs     土曜の予備実行が必要かどうかの判定
DESIGN.md                  UI を触るときのデザイン仕様
```

## 手元で更新する

```bash
node scripts/update-ranking.mjs    # 10〜20 分（外部サイトに負荷をかけないよう間隔を空けている）
node scripts/verify-ranking.mjs
```

確認だけしたいときは `--limit 5` で人数を絞れる。

重みや欠測の扱いだけ変えたいときは、再収集せずに計算し直せる。

```bash
node scripts/rescore.mjs --dry    # 順位がどう動くか確認するだけ
node scripts/rescore.mjs          # data/ranking.json に反映
```

## 自動更新

`.github/workflows/weekly-ranking-update.yml`

- **毎週金曜 10:00 JST**（cron は `0 1 * * 5` / UTC）に収集・検証・コミット。
- **毎週土曜 11:00 JST**（`0 2 * * 6`）に予備実行。`scripts/should-run.mjs` が
  `data/ranking.json` の生成時刻を見て、**30 時間以内に更新済みならスキップ**する。
  金曜が落ちていたときだけ回る。
- 手動実行（`workflow_dispatch`）も可。
- `verify-ranking.mjs` が落ちた場合はコミットしない。壊れたデータが公開されない。

> GitHub Actions の `schedule` はデフォルトブランチのワークフローしか動かない。
> このワークフローは main にマージされて初めて有効になる。

## 名簿を増やす・直す

`data/roster.json` の `actors` に足す。最低限 `name` と `genres` があれば動く
（`natalieId` / `achikochiSlug` は空なら名前で検索して解決する。固定したいときは書いておく）。

## 注意

公開データに基づく機械的な集計であり、俳優の実力や評価を示すものではない。
フォロワー数は各集計サイト・公開プロフィールの表示値をそのまま引いており、独自の推定値は含まない。
